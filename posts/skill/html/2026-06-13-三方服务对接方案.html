调用多个三方服务的统一封装解决方案

发布日期：2026-06-13
业务组件封装 架构优化 性能优化 Java 微服务

统一封装三方服务调用

一、核心思想

这套方案沿用「统一入口 + 两级路由 + 分层解耦 + 配置化对接」的设计内核，完美适配「单/多三方多接口、跨注册中心独立部署、前端不直连三方」的场景，核心逻辑可概括为5点：

  1. 前端完全隔离：所有三方服务调用均由后端承接，前端仅调用业务接口，完全不感知三方地址、鉴权与接口规范。
  2. 两级路由分发：第一级按「服务类型」区分不同三方（大模型/短信/三方业务），第二级按「操作类型」区分同服务下的具体接口（对话/模型构建/知识库），用路由映射替代硬编码分支判断。
  3. 面向接口扩展：所有服务、子接口均遵循统一处理器接口，新增服务/接口仅需新增实现类，自动注册进路由表，无需修改核心分发逻辑，符合开闭原则。
  4. 公共逻辑统一治理：鉴权、日志、异常处理、超时重试等通用能力，下沉到对应层级的入口处，实现一次编写、全局覆盖，消除重复代码。
  5. 跨注册中心兼容：不依赖统一服务发现，通过配置文件维护三方服务地址，采用HTTP直连调用，适配服务独立部署、分属不同注册中心的场景。

二、完整实现流程 + 对应代码

1. 第一步：定义全局统一规范（契约层）

目的：约定所有三方调用的入参、出参、处理器接口标准，是整个统一调用体系的基础契约。

// 1.1 通用请求对象：所有三方调用统一入参格式
@Data
public class ThirdPartyRequest {
    // 公共字段：请求ID、调用方标识
    private String requestId;
    private String caller;
    // 一级路由标识：服务类型（如 llm/sms）
    private String serviceType;
    // 二级路由标识：操作类型（如 chat/model_create）
    private String operateType;
    // 动态业务参数：不同接口存放各自的业务数据
    private Map<String, Object> bizParams;
}

// 1.2 通用返回对象：所有三方调用统一出参格式
@Data
public class ThirdPartyResult {
    private Boolean success;
    private String code;
    private String msg;
    private Map<String, Object> data;
}

// 1.3 顶层三方处理器接口：所有三方服务主处理器都实现该接口
public interface ThirdPartyHandler {
    // 执行三方调用
    ThirdPartyResult execute(ThirdPartyRequest request);
    // 返回服务类型，用于一级路由匹配
    String getServiceType();
}

2. 第二步：搭建一级路由（全局统一调用入口）

目的：作为所有三方调用的唯一入口，负责一级路由分发、全局公共逻辑处理，对应原文的KingdeeManagementServiceImpl。

@Slf4j
@Service
public class ThirdPartyInvokeService {

    // 一级路由表：key=服务类型，value=对应三方主处理器
    private final Map<String, ThirdPartyHandler> handlerMap = new ConcurrentHashMap<>();

    /**
     * Spring启动时自动注入所有ThirdPartyHandler实现类，自动组装路由表
     * 新增三方服务无需修改此处，自动注册
     */
    @Autowired
    public void initHandlers(List<ThirdPartyHandler> handlerList) {
        for (ThirdPartyHandler handler : handlerList) {
            handlerMap.put(handler.getServiceType(), handler);
        }
    }

    /**
     * 全局统一调用方法：业务层仅调用此方法
     */
    public ThirdPartyResult invoke(ThirdPartyRequest request) {
        // 1. 一级路由匹配
        ThirdPartyHandler handler = handlerMap.get(request.getServiceType());
        if (handler == null) {
            throw new ServiceException("不支持的三方服务类型：" + request.getServiceType());
        }

        // 2. 全局前置处理：日志、限流、全局参数校验
        log.info("三方调用开始，服务类型：{}，操作类型：{}，请求ID：{}",
                request.getServiceType(), request.getOperateType(), request.getRequestId());

        try {
            // 3. 转发到对应三方主处理器
            ThirdPartyResult result = handler.execute(request);
            // 4. 全局后置处理：埋点、监控
            log.info("三方调用结束，结果：{}", result.getSuccess());
            return result;
        } catch (Exception e) {
            // 5. 全局异常处理
            log.error("三方调用异常", e);
            ThirdPartyResult result = new ThirdPartyResult();
            result.setSuccess(false);
            result.setMsg("三方服务调用异常");
            return result;
        }
    }
}

3. 第三步：搭建二级路由（单服务主处理器 + 子接口规范）

目的：针对单个三方服务（如大模型），实现内部二级路由，复用该服务的公共鉴权、请求头、异常处理逻辑。

// 3.1 子操作处理器接口：大模型下所有子接口都实现该接口
public interface LlmOperationHandler {
    // 返回操作类型，用于二级路由匹配
    String getOperateType();
    // 执行具体接口调用
    ThirdPartyResult doExecute(String baseUrl, ThirdPartyRequest request);
}

// 3.2 大模型主处理器：实现顶层接口，负责二级路由+服务级公共逻辑
@Slf4j
@Service
public class LlmHandler implements ThirdPartyHandler {

    // 从配置文件读取地址、密钥（跨注册中心核心：配置化直连）
    @Value("${third-party.llm.base-url}")
    private String llmBaseUrl;
    @Value("${third-party.llm.api-key}")
    private String apiKey;

    @Autowired
    private RestTemplate restTemplate;

    // 二级路由表：key=操作类型，value=对应子接口处理器
    private final Map<String, LlmOperationHandler> operationMap = new ConcurrentHashMap<>();

    /**
     * 自动注入所有大模型子操作处理器，组装二级路由表
     * 新增大模型接口无需修改此处，自动注册
     */
    @Autowired
    public void initOperations(List<LlmOperationHandler> operationList) {
        for (LlmOperationHandler handler : operationList) {
            operationMap.put(handler.getOperateType(), handler);
        }
    }

    @Override
    public ThirdPartyResult execute(ThirdPartyRequest request) {
        // 1. 二级路由匹配
        LlmOperationHandler operation = operationMap.get(request.getOperateType());
        if (operation == null) {
            throw new ServiceException("大模型不支持该操作类型：" + request.getOperateType());
        }

        // 2. 服务级公共逻辑：统一鉴权、请求头
        HttpHeaders commonHeaders = new HttpHeaders();
        commonHeaders.set("Authorization", "Bearer " + apiKey);
        commonHeaders.setContentType(MediaType.APPLICATION_JSON);
        request.getBizParams().put("_commonHeaders", commonHeaders);

        // 3. 转发到子接口处理器执行
        return operation.doExecute(llmBaseUrl, request);
    }

    @Override
    public String getServiceType() {
        // 对应一级路由的服务类型编码
        return "llm";
    }
}

4. 第四步：实现具体子接口处理器

目的：每个接口单独实现，仅负责自身的参数组装、接口调用、结果解析，逻辑完全独立。

示例1：对话聊天接口
@Service
public class LlmChatOperation implements LlmOperationHandler {

    @Override
    public String getOperateType() {
        return "chat";
    }

    @Override
    public ThirdPartyResult doExecute(String baseUrl, ThirdPartyRequest request) {
        // 1. 提取业务参数
        String prompt = (String) request.getBizParams().get("prompt");
        String model = (String) request.getBizParams().getOrDefault("model", "gpt-4o");
        HttpHeaders headers = (HttpHeaders) request.getBizParams().get("_commonHeaders");

        // 2. 组装接口专属请求体
        LlmChatRequest chatRequest = new LlmChatRequest();
        chatRequest.setModel(model);
        chatRequest.setMessages(Collections.singletonList(new Message("user", prompt)));

        // 3. HTTP直连调用三方接口（跨注册中心，无需服务发现）
        String url = baseUrl + "/v1/chat/completions";
        HttpEntity<LlmChatRequest> entity = new HttpEntity<>(chatRequest, headers);
        ResponseEntity<LlmChatResponse> response = restTemplate.exchange(
                url, HttpMethod.POST, entity, LlmChatResponse.class
        );

        // 4. 转换为统一返回格式
        ThirdPartyResult result = new ThirdPartyResult();
        result.setSuccess(true);
        Map<String, Object> data = new HashMap<>();
        data.put("answer", response.getBody().getChoices().get(0).getMessage().getContent());
        result.setData(data);
        return result;
    }
}
示例2：模型构建接口
@Service
public class LlmModelCreateOperation implements LlmOperationHandler {

    @Override
    public String getOperateType() {
        return "model_create";
    }

    @Override
    public ThirdPartyResult doExecute(String baseUrl, ThirdPartyRequest request) {
        // 提取参数、组装请求体、调用接口、封装返回
        String modelName = (String) request.getBizParams().get("modelName");
        String datasetId = (String) request.getBizParams().get("datasetId");
        HttpHeaders headers = (HttpHeaders) request.getBizParams().get("_commonHeaders");

        ModelCreateRequest createRequest = new ModelCreateRequest();
        createRequest.setName(modelName);
        createRequest.setDatasetId(datasetId);

        String url = baseUrl + "/v1/models/create";
        HttpEntity<ModelCreateRequest> entity = new HttpEntity<>(createRequest, headers);
        ResponseEntity<ModelCreateResponse> response = restTemplate.exchange(
                url, HttpMethod.POST, entity, ModelCreateResponse.class
        );

        ThirdPartyResult result = new ThirdPartyResult();
        result.setSuccess(true);
        Map<String, Object> data = new HashMap<>();
        data.put("modelId", response.getBody().getModelId());
        result.setData(data);
        return result;
    }
}

5. 第五步：配置化地址管理（跨注册中心核心）

目的：不依赖注册中心，通过配置文件维护所有三方服务的访问地址，支持独立部署。

# application.yml 配置
third-party:
  llm:
    base-url: http://llm-service.xxx.com:9000  # 大模型服务独立地址
    api-key: sk-xxxxxxxxxxxx
  sms:
    base-url: http://sms-service.xxx.com:8080  # 短信服务独立地址
    sign: 【系统通知】

补充：需提前注入RestTemplate Bean，用于HTTP调用：

@Configuration
public class RestTemplateConfig {
    @Bean
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}

6. 第六步：业务层调用示例

目的：业务代码仅依赖统一入口，完全不感知三方对接细节。

@Service
public class AIService {

    @Autowired
    private ThirdPartyInvokeService thirdPartyInvokeService;

    // 调用大模型对话接口
    public String chat(String prompt) {
        ThirdPartyRequest request = new ThirdPartyRequest();
        request.setRequestId(UUID.randomUUID().toString());
        request.setServiceType("llm");       // 一级路由：大模型服务
        request.setOperateType("chat");     // 二级路由：对话接口
        Map<String, Object> params = new HashMap<>();
        params.put("prompt", prompt);
        request.setBizParams(params);

        ThirdPartyResult result = thirdPartyInvokeService.invoke(request);
        return (String) result.getData().get("answer");
    }

    // 调用模型构建接口
    public String createModel(String modelName, String datasetId) {
        ThirdPartyRequest request = new ThirdPartyRequest();
        request.setServiceType("llm");
        request.setOperateType("model_create"); // 二级路由：模型构建接口
        Map<String, Object> params = new HashMap<>();
        params.put("modelName", modelName);
        params.put("datasetId", datasetId);
        request.setBizParams(params);

        ThirdPartyResult result = thirdPartyInvokeService.invoke(request);
        return (String) result.getData().get("modelId");
    }
}

三、一次请求的完整调用链路

  1. 前端调用业务接口 → 进入业务Service层
  2. 业务Service组装参数，指定服务类型+操作类型，调用ThirdPartyInvokeService.invoke()
  3. 一级路由：根据服务类型匹配到LlmHandler大模型主处理器
  4. 二级路由：主处理器完成公共鉴权后，根据操作类型匹配到具体子接口处理器
  5. 子处理器组装请求参数，通过HTTP直连调用三方服务接口
  6. 结果逐层封装返回：子处理器 → 主处理器 → 统一入口 → 业务层 → 前端
