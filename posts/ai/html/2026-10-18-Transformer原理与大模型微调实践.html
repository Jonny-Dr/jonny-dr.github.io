Transformer 原理与大模型微调实践

学习目标：从传统 Transformer
的基本数据流开始，逐步理解位置编码、Attention、FFN、门控激活、残差与归一化，再过渡到现代大模型常见设计，最后掌握垂直领域
LoRA/QLoRA 微调与部署时的实际选择。

核心原则：如果目标是使用现成大模型完成微调和部署，重点是选模型、准备数据、配置训练、评估效果与部署优化；通常不需要从零编写神经网络或重新设计基础模型的层数、注意力结构和激活函数。

1. 先建立整体认识：一个 Transformer 大模型如何工作？

以常见的自回归语言模型（例如 Decoder-only
LLM）为例，可以把数据流简化为：

flowchart TD
    A[输入文本] --> B[Tokenizer：切分为 Token]
    B --> C[Token ID / Embedding]
    C --> D[位置编码：例如 RoPE]
    D --> E[重复堆叠的 Transformer Blocks]
    E --> F[输出投影与词表概率]
    F --> G[预测下一个 Token]
    G --> H{是否结束生成？}
    H -- 否 --> E
    H -- 是 --> I[输出文本]

每个 Transformer Block 可以粗略理解为两个主要子层：

flowchart TD
    X[输入隐藏状态] --> A[Attention：Token 之间交换上下文]
    A --> R1[残差连接与归一化]
    R1 --> F[FFN：逐 Token 加工特征]
    F --> R2[残差连接与归一化]
    R2 --> Y[输出隐藏状态]

上图是概念图。实际采用 Pre-LN 还是
Post-LN，会改变归一化相对于子层和残差连接的位置，后文会专门说明。

两个核心模块的分工

  • Attention（注意力）：让一个 Token 根据当前任务需要，从其他可见
    Token
    中获取信息。例如，处理"它"时，模型可以关注前文中与"它"对应的人或事物。
  • FFN（前馈网络）：对每个 Token
    的隐藏特征分别进行非线性变换与加工。它不负责直接在 Token
    之间传递信息，而是处理 Attention 汇总后的特征。
  • 残差连接（Residual
    Connection）    ：让子层输入可以沿着一条相对直接的路径传到后面，有助于深层网络训练。
  • 归一化（Normalization）：调整隐藏特征的尺度，帮助训练更稳定。

一个大模型通常堆叠许多 Transformer Block。模型层数、隐藏维度、Attention
结构等通常由基础模型设计者决定。

2. Token、Embedding 与位置编码

2.1 Token 与 Embedding

Tokenizer 将文本转换成 Token ID。Token
不一定对应一个完整汉字或单词，也可能是词的一部分、标点或其他子词单元。

Embedding 再将每个 Token ID
映射成一个向量。模型后续处理的是这些向量，而不是直接处理原始字符串。

2.2 为什么需要位置信息？

Attention 本身需要额外机制来理解序列中 Token
的位置与顺序。位置编码就是为模型提供位置信息的一类方法。

2.3 RoPE：旋转位置编码

RoPE（Rotary Position Embedding）是许多现代 LLM 使用的位置编码方法。

可以先记住以下要点：

  • RoPE 将位置信息融入 Attention 中的 Query（Q）和 Key（K）。
  • 它通过对 Q、K 的特征进行与位置有关的旋转，使 Q 与 K
    的点积能够体现相对位置关系。
  • 通常不对 Value（V）做同样的 RoPE 旋转。
  • RoPE
    不意味着距离越远，注意力权重必然越低。注意力还取决于内容相关性、模型参数、掩码等因素。
  • 不同模型可能对 RoPE 的频率、缩放方式和长上下文扩展方法作不同处理。

在使用预训练模型微调时，一般不需要自己实现
RoPE；只需要理解它的作用，并在选模型时考虑上下文长度及其长上下文能力。

3. Attention：理解结构，而不是微调时重新设计它

Attention 的核心思路是：根据 Query 与 Key
的匹配程度计算注意力权重，再使用这些权重汇总 Value 中的信息。

常见 Attention 结构

  • MHA（Multi-Head
    Attention，多头注意力）    ：使用多个注意力头学习不同的信息关联。
  • MQA（Multi-Query Attention）：多个 Query 头共享 Key 和
    Value，通常能减少 KV Cache 开销。
  • GQA（Grouped-Query Attention）：多个 Query 头分组共享
    Key/Value，常用于平衡效果与推理效率。

这些结构会影响模型架构和推理资源需求，尤其是 KV Cache 的存储与访问成本。

Attention 结构与计算后端不是一回事

例如 SDPA、FlashAttention
等，主要是对注意力计算进行高效实现。它们不一定意味着模型的 Attention
数学结构发生改变。

在常规微调中：

  • 通常沿用基础模型原有的 MHA、GQA 或 MQA 结构。
  • 可以根据硬件、软件版本和模型兼容性，选择合适的计算后端。
  • 如果希望更低的推理成本，通常优先在选模型时考虑
    GQA、上下文长度、模型规模等因素，而不是随意把已训练好的模型结构改掉。

4. FFN：从传统前馈网络到门控式 FFN

4.1 传统 FFN

传统 Transformer 的 FFN 通常包含：

  1. 线性变换，将隐藏特征映射到更宽的中间维度；
  2. 使用非线性激活函数，例如 ReLU 或 GELU；
  3. 再通过线性变换，映射回模型隐藏维度。

简化结构：

flowchart LR
    A[输入特征] --> B[线性变换]
    B --> C[激活函数：ReLU / GELU]
    C --> D[输出线性变换]
    D --> E[输出特征]

FFN 的主要职责是逐 Token 加工特征。它与 Attention 分工不同：Attention
负责跨 Token 交换上下文，FFN 负责在特征维度上做进一步变换。

4.2 GELU 与 ReLU

  • ReLU：负值变为 0，正值直接通过。结构简单，但在零点不平滑。
  • GELU：根据输入值平滑调整信号的保留程度；负值通常受到抑制，较大的正值通常接近直接通过。
  • GELU 是传统 Transformer 与许多神经网络中常见的激活函数，但现代 LLM
    也大量使用门控式 FFN。

4.3 GeGLU：不是简单替换一个激活函数

GeGLU 是一种门控式 FFN 结构。它不只是把传统 FFN 中的 ReLU 换成
GELU，而是增加了两条线性变换分支：

flowchart TD
    X[输入特征] --> A[特征分支：线性变换]
    X --> B[门控分支：线性变换]
    B --> C[GELU 激活]
    A --> D[逐元素相乘]
    C --> D
    D --> E[输出线性变换]
    E --> Y[输出特征]

可以这样理解：

  • 一条分支产生待加工的特征；
  • 另一条分支产生门控信号，并经过激活函数；
  • 两条分支逐元素相乘，控制不同特征被增强、保留或抑制的程度；
  • 最后通过输出线性层得到结果。

门控真正发生的位置，是两个分支的逐元素乘法。 GELU
负责生成门控分支的非线性信号，但它本身并不等于完整的门控机制。

4.4 GeGLU 与 SwiGLU 对比

项目 GeGLU SwiGLU

门控分支激活函数 GELU SiLU / Swish

是否采用两条线性分支 是 是

是否逐元素相乘 是 是

主要作用 根据输入特征调节另一分支的信息 根据输入特征调节另一分支的信息

常见场景 门控式 FFN 的一种设计 许多现代 LLM 使用的门控式 FFN

4.5 GELU 与 SiLU 的门控机制，用一句话理解

  • GELU：平滑地调整门控信号的保留程度，通常抑制负值、让较大的正值较充分地通过。
  • SiLU：将输入与随输入平滑变化的系数相乘，形成连续、平滑的非线性门控信号。

两者都不是严格的 0 到 1 二值开关，门控分支输出也可能是负值。

SwiGLU 常见于现代 LLM，但不能简单断言它在所有任务上都一定优于
GeGLU；实际效果与模型、训练数据和训练配置有关。

5. Residual：残差连接是什么？

Residual
Connection（残差连接，也叫跳跃连接）不是一种独立的激活函数，也不是一定要单独定义的网络层，而是一种连接方式。

它的基本思想是：让输入绕过一个子层，再与该子层的输出相加。

flowchart LR
    X[输入 X] --> F[子层 F]
    X --> ADD[逐元素相加]
    F --> ADD
    ADD --> Y[输出]

概念上可以写作"输入 + 子层输出"，但真实 Transformer
的子层中可能包含归一化、Attention、FFN、Dropout 等步骤。

注意：

  • 残差相加的不是一定刚经过激活函数的那一刻的输出，而是子层按架构定义完成后的输出。
  • 残差连接为信息和梯度提供较直接的路径，有助于训练深层网络。
  • 残差相加要求两条路径的张量形状兼容；模型设计通常会保证这一点。

6. Post-LN 与 Pre-LN：归一化放在哪里？

Pre-LN 和 Post-LN 描述的是归一化层相对于子层及残差连接的放置位置。

6.1 Post-LN

经典 Transformer 采用的典型形式是 Post-LN：子层先计算，再与原始输入相加，之后进行归一化。

概念结构：

flowchart LR
    X[输入 X] --> F[子层]
    X --> ADD[残差相加]
    F --> ADD
    ADD --> LN[LayerNorm]
    LN --> Y[输出]

特点：

  • 归一化位于子层输出与残差输入相加之后。
  • 是经典 Transformer 的代表性设计。
  • 在较深的网络中，训练稳定性可能更依赖初始化、学习率等设置。

6.2 Pre-LN

Pre-LN 将归一化放在子层计算之前，子层输出再与原始输入相加。

概念结构：

flowchart LR
    X[输入 X] --> ADD[残差相加]
    X --> NORM[归一化]
    NORM --> F[子层]
    F --> ADD
    ADD --> Y[输出]

特点：

  • 残差路径更加直接。
  • 通常更容易训练较深的 Transformer。
  • 常见于许多现代 Transformer 和 LLM，但具体实现可能包含额外的最终归一化或其他细节。

6.3 两者如何选择？

维度 Post-LN Pre-LN
归一化位置 残差相加之后 子层计算之前
典型代表 经典原始 Transformer 结构 许多现代深层 Transformer / LLM
深层训练 通常需要更谨慎地处理训练稳定性 通常更容易训练深层模型
新项目怎么选 复现特定 Post-LN 架构时按原设计 从零研究深层模型时常作为起点之一
微调已有模型 沿用基础模型结构 沿用基础模型结构

关键建议： 对预训练模型做 LoRA/QLoRA 微调时，不要因为听说 Pre-LN 更容易训练，就把原本的 Post-LN 模型直接改成 Pre-LN。模型权重是基于原始架构训练出来的，改变归一化位置会改变计算行为。

Pre-LN 并不保证训练一定稳定。初始化、学习率、残差缩放、数据和训练策略仍然重要。DeepNorm 等方案就是针对深层 Transformer 训练稳定性提出的相关设计之一。

7. LayerNorm、RMSNorm 与 DeepNorm

7.1 LayerNorm

LayerNorm（层归一化）通常针对单个 Token
的隐藏特征维度进行归一化。它会根据特征的均值和方差调整数据尺度，再通过可学习参数进行缩放和平移。

作用是帮助隐藏状态保持较合适的数值分布，从而使训练更稳定。

7.2 RMSNorm

RMSNorm（均方根归一化）与 LayerNorm 的主要区别是：

  • LayerNorm 通常先减去均值，再按标准差归一化。
  • RMSNorm 不做减均值操作，而是按特征的均方根尺度进行归一化。
  • RMSNorm 通常采用可学习缩放参数，通常不使用 LayerNorm
    式的可学习平移参数。
  • RMSNorm 计算相对简洁，被许多现代 LLM 使用。

7.3 LayerNorm 与 RMSNorm 怎么选？

维度 LayerNorm RMSNorm

是否减去均值 是 否
是否使用尺度归一化 是 是，使用均方根尺度
常见参数 缩放与平移 通常有缩放参数
计算特点 操作相对多一些 通常更简洁
选择原则 按模型架构和实验结果 按模型架构和实验结果

微调已有模型时通常不需要替换归一化算法。如果某个基础模型使用
RMSNorm，继续使用它；如果使用 LayerNorm，也应沿用其设计。

7.4 DeepNorm 是什么？

DeepNorm 不是 LayerNorm 的简单升级版，也不是另一种常规归一化算法。
它是一套针对深层 Transformer 的设计方案，涉及残差路径的缩放以及与之配套的初始化/参数缩放策略，目标是改善深层网络的训练稳定性。

不要将现代 LLM 简化成固定组合"RoPE + SwiGLU + DeepNorm"。不同模型会使用不同的组合；
许多现代 LLM 的常见组合更接近：

  • RoPE；
  • SwiGLU；
  • RMSNorm；
  • Post-LN 或与 Pre-LN 类似的归一化布局；
  • 与模型目标匹配的 Attention 结构。

这只是常见趋势，不是所有模型的统一标准。

7.5 不要混淆的两个维度

  • Pre-LN / Post-LN：决定归一化放在子层计算的前面还是残差相加的后面。
  • LayerNorm / RMSNorm：决定归一化本身使用什么算法。

它们是不同维度，不能当作互斥的同一组选项。

8. 从架构学习过渡到模型微调：最重要的认识

如果目标是掌握现成模型的微调和部署，需要区分两类工作。

8.1 模型架构设计

通常由基础模型的研发者决定：

  • Transformer 有多少层；
  • 隐藏维度、注意力头数等模型尺寸；
  • 使用 MHA、GQA 还是 MQA；
  • FFN 使用 GELU、GeGLU、SwiGLU 等哪种设计；
  • 使用 LayerNorm、RMSNorm，以及 Pre-LN / Post-LN 等布局；
  • 使用何种位置编码。

这些设计通常已经写入模型结构定义和配置中，并且与预训练权重相匹配。

8.2 模型微调

使用现成预训练模型时，实际需要重点决定的内容包括：

  • 选择哪个基础模型；
  • 是否真的需要微调，还是 RAG 已足够；
  • 训练目标与数据格式；
  • LoRA / QLoRA 方案；
  • LoRA 的 rank、target modules、dropout 等参数；
  • 学习率、批次大小、训练轮数、序列长度；
  • 验证方法、过拟合控制；
  • 量化、适配器合并、推理框架和服务部署方式。

因此，微调不是从零重新编写神经网络，而是在已有架构上训练一部分参数，或在特定方案下更新更多参数。

9. 垂直领域微调前，先判断是否真的需要微调

并不是所有领域需求都应该通过 LoRA/QLoRA 解决。

业务需求 优先考虑的方案 原因

查询不断变化的企业文档、制度、知识库 RAG 知识可以更新，不必每次重新训练模型

希望模型遵循特定回答格式或指令习惯 SFT，可结合 LoRA 训练样本可以教会模型目标行为

让模型熟悉行业语言、术语和文本分布 领域继续预训练或 SFT，视数据类型决定 需要先明确是语言适应还是任务行为适应

需要查询数据库、调用 API、执行流程 工具调用 / 工作流 / Agent，必要时配合微调 仅微调不等于模型自动获得外部工具能力

需要模型具备强推理或编码能力 优先选能力合适的基础模型，再评估训练方案 微调不一定能弥补基础模型能力差距

RAG 和微调并不互斥。企业应用可能同时使用 RAG
来获取最新事实，使用微调来改善输出格式、术语和任务行为。

10. LoRA 与 QLoRA：基本原理和选择

10.1 LoRA

LoRA（Low-Rank Adaptation，低秩适配）冻结基础模型的大部分或全部原始权重，在选定的线性层旁添加可训练的低秩适配参数。

它的目标是用相对少的可训练参数适应下游任务，而不是把整个模型从头训练一遍。

10.2 QLoRA

QLoRA 在 LoRA 的基础上，通常将冻结的基础模型权重量化到 4 bit 等较低精度，再训练 LoRA 适配器，以降低显存占用。

需要注意：

  • QLoRA 通常能降低基础模型权重的显存成本，但训练仍需要存储激活值、梯度和其他状态。
  • 量化可能影响数值表现，实际效果依赖模型、数据、量化方法和训练配置。
  • LoRA 与 QLoRA 都不意味着重新设计 Attention 或 FFN 架构。

10.3 LoRA 和 QLoRA 怎么选？

维度 LoRA QLoRA

基础模型加载精度 常见 FP16 / BF16 等 常见 4 bit 量化

基础模型权重是否更新 通常冻结 通常冻结

是否训练适配器 是 是

显存占用 通常较高 通常较低

适合场景 显存充足，希望减少量化因素 显存有限，希望微调更大的模型

注意事项 仍需考虑激活值、批次和序列长度 需关注量化兼容性与潜在效果变化

实操建议： 如果显存充足，可先用 LoRA 建立基线；显存不足时，再评估
QLoRA。选择应基于真实显存、吞吐量和效果，而不是认为 QLoRA
在所有情况下都更好。

11. LoRA 实际参数怎么选？

11.1 target_modules：把 LoRA 加到哪些线性层？

以常见的 Llama / Qwen 类 Decoder-only Transformer 为例，模块名称可能包括：

Attention 部分

  • q_proj：生成 Query；
  • k_proj：生成 Key；
  • v_proj：生成 Value；
  • o_proj：将注意力结果映射回隐藏维度。

FFN 部分

  • gate_proj：生成门控分支；
  • up_proj：生成另一条特征分支；
  • down_proj：将扩展后的特征映射回隐藏维度。

具体命名取决于模型架构，并非所有模型都使用这些名称。

选择方式 特点 适合的实验顺序

只对 q_proj、v_proj 可训练参数较少 作为轻量基线之一
等部分 Attention 层注入

覆盖更多 Attention 可调整范围更广 在基线不足时对比
投影层

覆盖 Attention 和 FFN 可训练参数通常更多 需要更强适应能力且资源允许时试验
的线性层

LoRA 并不只能用于 Attention。某些模型和 PEFT 配置支持对所有线性层进行适配，例如使用 all-linear这类目标配置；实际可用性要依据框架版本和模型结构确认。

推荐实验顺序：

  1. 先使用基础模型或模型教程推荐的目标模块配置。
  2. 如果效果不足，比较扩大 Attention 投影层范围是否有收益。
  3. 再尝试覆盖 FFN 等更多线性层。
  4. 同时记录效果、可训练参数量、显存和训练时间。

每轮尽量只改变一个主要因素，才能判断提升来自哪里。

11.2 r：LoRA 的 rank

r 是 LoRA 的秩，可以理解为适配器的可训练调整空间大小。

  • 较小的 r：可训练参数少，资源开销较低，但表达能力可能受限。
  • 较大的 r：调整空间更大，参数和资源开销通常也会增加，但不保证效果更好。

可以从 r=8 或 r=16 开始，并比较 r=8、16、32 等候选配置。这些是实验起点，不是适用于所有模型和任务的固定标准。

r 不是 Transformer 层数，也不是 Attention 头数。

11.3 其他训练参数

参数 控制什么 需要关注的现象

学习率 参数每次更新的幅度 过大可能不稳定，过小可能学习不足

Epoch 完整遍历训练集的次数 过多可能过拟合

Batch size 每次更新使用的样本量 受显存限制，也影响梯度噪声

Gradient accumulation 累积几次梯度后更新 显存有限时可模拟更大的有效批次

Warmup 训练初期逐渐增加学习率 有时能帮助训练更平稳地启动

LoRA dropout 对适配器分支施加 dropout 数据较少或过拟合时可尝试

Sequence length 单个样本的最大序列长度 越长通常越占显存与计算资源

先使用框架或模型教程提供的可靠基线配置，再根据验证集做小规模对照实验。不要一开始就同时大幅修改所有参数。

12. 一套可执行的垂直领域微调流程

假设目标是将一个开源中文模型适配为企业内部技术问答助手，可以按以下步骤推进。

flowchart TD
    A[明确业务目标与验收指标] --> B{是否必须微调？}
    B -- 否：主要是查知识 --> C[优先评估 RAG]
    B -- 是：需要学习行为/格式 --> D[选择基础模型]
    C --> E[构建评测集并验证方案]
    D --> F[准备和清洗训练数据]
    F --> G[划分训练集、验证集、测试集]
    G --> H[选择 LoRA 或 QLoRA]
    H --> I[配置 target_modules、rank 和训练参数]
    I --> J[小规模试训]
    J --> K[评估效果、显存、时延与过拟合]
    K --> L{达到业务标准？}
    L -- 否 --> M[定位问题并一次调整一个主要因素]
    M --> J
    L -- 是 --> N[保存适配器或按需合并权重]
    N --> O[部署与真实业务测试]
    O --> P[监控、回归评测和迭代]

第一步：明确目标

不要只写"提升专业能力"。应该具体定义：

  • 哪些问题要答对；
  • 输出必须遵循什么格式；
  • 哪些情况应该拒答或要求补充信息；
  • 如何评价准确性、完整性、格式正确率、延迟与成本。

第二步：选择基础模型

重点评估：

  • 中文、代码、推理和指令遵循能力；
  • 模型规模和推理成本；
  • 上下文长度；
  • 许可证与商用条件；
  • 显存和部署框架兼容性。

如果基础模型能力不足，应优先比较其他基础模型，而不是先修改层数或激活函数。

第三步：准备数据

SFT数据通常由输入与期望输出组成。需要检查答案正确性、重复样本、格式一致性和数据覆盖范围。

训练集、验证集和测试集应相互独立。尤其要避免近似重复样本同时出现在训练集与测试集中，否则测试结果可能过于乐观。

第四步：建立基线

  • 使用模型推荐的 LoRA 配置；
  • 选择合适的 rank；
  • 先用小规模数据验证训练流程；
  • 记录基础模型与微调后的评测结果；
  • 保存配置、数据版本和模型版本，确保实验可复现。

第五步：定位问题，而不是盲目调参

观察到的问题 优先排查

训练损失不下降 数据格式、学习率、训练流程、梯度与目标设置
训练效果好但验证效果差 过拟合、样本重复、训练与验证分布差异
输出格式经常错误 训练样本格式、模板、目标答案一致性
显存不足 量化、批次大小、梯度累积、序列长度、检查点等
模型仍然缺少最新事实 是否需要 RAG，而不是继续训练记忆知识
效果提升不明显 基础模型能力、数据质量、训练目标、rank 和目标模块

第六步：部署前验证

部署前除了离线测试，还应验证：

  • 真实业务输入下的输出质量；
  • 首 Token 延迟、整体响应时间和并发吞吐量；
  • 显存占用与 KV Cache；
  • 适配器加载、合并与回滚流程；
  • 量化后质量是否仍满足业务标准；
  • 监控、日志、版本管理和数据安全要求。

LoRA
适配器可以与基础模型分开管理，也可以在需要时按工具链支持的方式合并。是否合并取决于部署框架、服务方式、切换适配器的需求和量化流程。

13. 小结

Transformer 基础

  • Attention 负责 Token 之间交换上下文；FFN 负责逐 Token 加工特征。
  • RoPE 将位置信息融入 Q/K 的计算，不代表距离越远注意力必然越小。
  • GeGLU 和 SwiGLU 都是门控式 FFN，不只是简单替换传统 FFN 的激活函数。
  • GeGLU 的门控分支使用 GELU；SwiGLU 的门控分支使用 SiLU/Swish。
  • Residual 是跳跃连接；Post-LN / Pre-LN 代表归一化相对于子层和残差的放置位置。
  • LayerNorm 与 RMSNorm 是不同的归一化算法；DeepNorm 则是一套针对深层 Transformer 的残差缩放与初始化相关方案。

微调与部署

  • 常规 LoRA/QLoRA 微调通常不需要重写 Transformer，也不需要手动替换层数、Attention 或激活函数。
  • 基础模型的架构通常与预训练权重相匹配，微调时优先保持不变。
  • 真正需要重点掌握的是基础模型选择、训练数据、LoRA 的 rank 和目标模块、学习率、训练轮数、评估与部署。
  • target_modules 决定 LoRA 注入哪些线性层；r 决定适配器的秩，不是模型层数。
  • LoRA 显存开销通常更高；QLoRA 通过低比特量化基础模型权重来降低显存需求，但效果需要实际验证。
  • 企业知识问答不一定必须微调；动态知识往往适合 RAG，行为与格式适配则可以考虑 SFT，二者也能组合。
  • 通过独立验证集和真实业务指标来决定是否继续调整，而不是只看训练损失。

一句话总结： 学习 Transformer 架构，是为了理解模型与做出正确选型；做垂直领域微调时，优先沿用预训练模型的架构，把精力放在数据、LoRA/QLoRA 配置、评估和部署上。
