1. NLP 发展的四大范式

NLP 的发展可以划分为四大范式，每一代范式都在降低人工成本、提升模型效果。

范式 名称 核心方法 特点与进步
第一范式 基于传统机器学习模型 TF-IDF 特征 + 朴素贝叶斯等机器学习算法 效果天花板低，严重依赖特征工程的质量
第二范式 基于深度学习模型 word2vec 特征 + LSTM 等深度学习算法 相比第一范式，准确率有所提高，特征工程工作量减少
第三范式 基于预训练模型 + fine-tuning BERT + fine-tuning 的 NLP 任务 准确度显著提高，模型变大，但小数据集就能训练出好模型
第四范式 基于预训练模型 + Prompt + 预测 BERT + Prompt 范式 训练所需训练数据显著减少

各范式的核心思想详解

第一范式：手工特征 + 传统机器学习

  • 核心思想：依赖专家的领域知识，从原始文本中手动抽取关键特征（如 TF-IDF），然后喂给传统机器学习模型（如朴素贝叶斯、SVM）。
  • 比喻：这就像传统工匠做一把椅子，需要老师傅亲自去选木材、打磨每一个榫卯。特征工程就是那个极其依赖"老师傅"手艺的环节。
  • 特点：效果天花板低，严重依赖特征工程的质量。

第二范式：浅层词向量 + 深度学习

  • 核心思想：通过神经网络（如 Word2Vec）自动学习词语的分布式向量表示（词向量），再输入深度学习模型（如 LSTM、CNN）。
  • 重大进步：实现了特征的自动学习，大大减轻了特征工程负担，模型准确率提升。
  • 局限：模型仍是为特定任务"从零开始"训练，每次任务都需要大量标注数据。

第三范式：预训练 + 微调 —— 当前工业界的基石

  • 核心思想：这是"大模型"时代的开端，核心分两步：
    • 预训练：在海量无标注文本上，通过自监督学习（如掩码语言模型 MLM）学会语言的通用知识，产出预训练模型（如 BERT、GPT）。
    • 微调（fine-tuning）：在预训练好的"通用大脑"基础上，用少量特定任务的标注数据进行"二次训练"，使其适配下游任务（如文本分类、问答）。
  • 重大进步：实现了"大力出奇迹"，模型精度显著提高；由于有了强大的预训练模型，只需小数据集即可获得很好的效果。

第四范式：预训练 + 提示 —— 通向未来的方向

  • 核心思想：最具革命性的一步。不再需要"微调"模型参数，而是通过设计自然语言提示（Prompt），直接引导预训练模型完成任务。
  • 例子：不让模型做"情感分类"，而是让它完成句子："这句话的情感是：'这部电影很棒'"。
  • 重大进步：
    • 训练数据锐减：通常只需几个或零个示例（少样本/零样本学习），无需准备大量标注数据。
    • 统一框架：所有 NLP 任务都可被重新表述为"文本填充"或"文本生成"问题。

2. Prompt 技术的发展时间线

Prompt 技术的发展沿超大规模语言模型和小规模语言模型两条路径并行推进。

2.1 超大规模语言模型路径（"暴力美学"）

时间 里程碑
2020.05 OpenAI 发布 GPT-3，提出 Demonstration 概念
2021.10 Google 发布 FLAN（only model），提出 Instruction-tuning
2022.01 In-Context Learning 研究（如 MetaICL、CBU）
2022.04 Google 发布 LaMDA（137B），引入对话 Prompt
2023.03 Google 发布 PaLM（540B），使用 Chain-of-Thought；OpenAI 发布 GPT-4

2.2 小规模语言模型路径（"精巧工艺"）

时间 里程碑

2021.03 ~ 2021.10 PPT、P-tuning、Prefix-tuning 等混合模板
2021.12 ~ 2022.05 MetaPrompt Tuning、ProQA 等提出统一模型
2022.01 ~ 2022.05 Prompt 在各种下游任务的应用
2022.05 ~ 2023.03 Prompt 技术在小模型上的探索

2.3 两条发展路径

第一条路径：超大规模语言模型的"暴力美学"

  • 代表：GPT-3 这样的千亿级模型。
  • 发展逻辑：当模型的容量和训练数据足够庞大时，本身已具备极强泛化能力，对提示精细设计的依赖度降低。
  • 三大技术：
    1. 上下文学习（In-Context Learning, ICL）：不更新模型参数，仅通过在输入中提供任务描述和几个示例（演示），让模型通过上下文理解任务并完成推理。意义在于证明超大型模型具备惊人的"举一反三"少样本甚至零样本学习能力，彻底改变人机交互范式。
    2. 指令微调（Instruction Tuning）：在 ICL 基础上，用海量的自然语言指令与对应输出数据微调模型，使其泛化理解并执行各种未见过的指令。意义在于让模型变得"听话"，使用门槛极大降低，ChatGPT 的成功正是这一路径的辉煌成果。
    3. 思维链（Chain-of-Thought, CoT）：在提示中不仅给出答案，更给出得到答案的中间推理步骤，从而激发大模型的复杂推理能力。意义在于将 AI 能力边界从感知、记忆扩展到复杂逻辑推理，是通向更通用人工智能的关键一步。

第二条路径：小规模语言模型的"精巧工艺"

  • 对于参数较少的模型，不具备 GPT-3 那样的"通才"能力，因此研究重点放在如何通过技术手段"雕刻"出最有效的提示。
  • 离散提示优化：将提示词（模板和标签词）视为离散令牌，用算法（强化学习、梯度搜索）自动搜索或生成效果更好的提示组合。意义在于开启提示自动化大门，但搜索空间巨大、优化困难。
  • 连续提示优化（重大突破）：真正的范式转变。不再纠结具体的提示词语，而是直接在小模型的可训练参数空间中，学习一段"连续的提示向量"。代表工作为 P-Tuning 和 P-Tuning v2。
    • 比喻：不再是寻找"打开保险柜的密码"，而是直接"配制一把能开锁的化学溶液"。
    • 意义：极大提升提示调优的效率和效果，让中小模型也能媲美大模型在特定任务上的性能，推动提示调优的普及。

3. Prompt-Tuning 的鼻祖：GPT-3

GPT-3 开创性地提出 In-context Learning（上下文学习） 思想：无须修改模型即可实现 few-shot、zero-shot 学习；同时引入 Demonstrate Learning（演示学习），即让模型知道与标签相似的语义描述，提升推理能力。

一句话概括：GPT-3 证明——当模型足够庞大和智能后，你只需要用自然语言"引导"它，而不是"改造"它。

3.1 GPT-3 的三大开创性贡献

  1. In-Context Learning（上下文学习）：最根本的突破。一个足够强大的模型，无需更新任何参数，仅通过给予任务描述或几个示例，就能理解并执行新任务。比喻：像给天才看过几道例题，他就能瞬间领悟并解出同类型的新题。它彻底改变了"一任务一模型"的传统范式。

  2. Few-Shot / Zero-Shot Learning（少样本/零样本学习）：ICL 思想的具体体现。

    • Zero-Shot：只给任务指令（如"请将英文翻译成中文："），不给例子。
    • Few-Shot：给少量示例（如 1-3 个例子）。
    • 意义：极大降低对标注数据的依赖，让 AI 应用更灵活、更普适。

  3. Demonstrate Learning（演示学习）：不仅是给例子，而是通过例子让模型理解与标签相关的语义描述，从而提升推理能力。这为后来更复杂的"思维链（CoT）"技术埋下伏笔。

3.2 GPT-3 面临的三大现实瓶颈

  1. 模型规模巨大，难以应用：参数动辄千亿，训练和部署成本极高，是只有少数巨头才能玩得起的"奢侈品"，无法在真实产业场景中普及。
  2. 能力严重依赖模型规模：ICL 的"神奇"能力在参数规模小的模型上效果急剧下降。没有 GPT-3 的体量，这套方法就不 work。
  3. 提示设计简单，泛化性能低：GPT-3 自带的 Prompt 通常比较简单直接，对于复杂任务，这种简单提示泛化能力不强、效果不稳定。

3.3 从瓶颈到新生：Prompt-Tuning 的使命

正是因为上述瓶颈，尤其是"大模型才有效、小模型无效"的核心矛盾，研究者开始思考：能否研究出一种方法，让参数规模较小的模型，也能具备甚至超越 GPT-3 通过提示激发出的强大能力？

答案就是 Prompt-Tuning。 后续出现的 P-Tuning、Prompt-Tuning v2 等一系列技术，根本目标就是通过连续提示、参数高效微调等精巧技术，在中小型模型上"复现"甚至"超越" GPT-3 在 ICL 上展现的能力，同时实现模型的轻量化与可部署性。

4. PET 模型：Pattern-Verbalizer-Pair（PVP）

PET（Pattern-Exploiting Training） 出自论文 《Exploiting Cloze Questions for Few Shot Text Classification and Natural Language Inference》（EACL 2021）。

  • 从论文题目可以看出：Prompt-Tuning 启发于文本分类任务，并试图将所有的分类任务转换为与 MLM（掩码语言模型）一致的完形填空（Cloze） 任务。
  • PET 模型提出两个很重要的组件，合称 PVP：

4.1 两大组件：PVP

组件一：Pattern（Template）—— 设计"填空题的题干框架"

  • 记作 T，即上文提到的 Template，是额外添加的、带有 [MASK] 标记的短文本。
  • 通常一个样本只有一个 Pattern；不同任务、不同样本可能有更适合自己的 Pattern，因此如何构建合适的 Pattern 是 Prompt-Tuning 的研究点之一。
  • 定义：指的是我们额外添加的、包含一个 [MASK] 标记的短文本。
  • 作用：对原始输入文本进行"包装"，把一个分类问题"伪装"成掩码语言模型任务。
  • 举例：对于句子"我喜欢这部电影。"和情感分析任务，一个 Pattern 可以是：[原始句子]。总体而言，这是一部很[MASK]的电影。，包裹后即："我喜欢这部电影。总体而言，这是一部很[MASK]的电影。"
  • 挑战与研究方向：如何为不同任务构建最合适的 Pattern，是 Prompt-Tuning 的一大研究重点。一个好的 Pattern 能极大提升模型性能。

组件二：Verbalizer —— 建立"填空题答案与分数的对应关系"

  • 记作 V，即标签词的映射。对于具体分类任务，需要选择指定的标签词（label word）。
  • 例如情感分析中，期望 Verbalizer 可能是 positive 和 negative（类标签）。不同任务有相应 label word，但 Verbalizer 的构建需要取决于对应的 Pattern，因此如何构建 Verbalizer 是另一个研究挑战。
  • 定义：负责建立"模型预测出的词语"与"最终需要的分类标签"之间的映射关系。
  • 作用：模型只能预测一个词（如"精彩"），但我们需要的是一个类别标签（如"正面情感"）。Verbalizer 就是这座"桥梁"。
  • 举例：预先定义好——预测词"精彩""出色""好看"等都映射到类别"正面"；预测词"无聊""糟糕""难看"等都映射到类别"负面"。

4.2 PET 模型的工作流程与意义

  1. 包裹：用设计好的 Pattern 将原始文本包装成完形填空形式。
  2. 预测：让 MLM 模型预测 [MASK] 位置的词。
  3. 映射：通过 Verbalizer，将预测出的词映射到最终的分类标签。

4.3 PET 模型的训练目标公式

基于 Pattern-Verbalizer-Pair（PVP） 组件的训练目标：

p(y|x) = ∏_{j=1}^{n} p([mask]_j = V(y) | T(x))
  • 目标：计算在输入句子 x 的前提下，其正确标签 y 的概率 p(y|x)，并最大化这个概率。
  • T(x)（Pattern 函数）：将原始输入句子 x 用设计好的模板进行包装。例如 x = "我喜欢这部电影。" 被包装为 T(x) = "我喜欢这部电影。总体而言，这是一部很[MASK]的电影。"
  • V(y)（Verbalizer 函数）：将分类标签 y 映射到具体标签词。例如标签 y="正面"，可定义 V(y) = "精彩"。
  • 公式含义：句子 x 属于类别 y 的概率，等于模型在模板化后的句子 T(x) 中，预测出 [MASK] 位置是标签词 V(y) 的概率。
  • 一句话总结：PET 通过将分类任务转化为"让模型在特定模板下预测出特定标签词"的概率问题，来训练模型。

4.4 当前最需关注的问题

基于 PVP 框架，最需要关注的问题是如何选择或构建合适的 Pattern 和 Verbalizer。一种简单的方法是根据特定任务的性质和先验知识人工设计模板。注意：在同样的数据集和训练条件下，选择不同的 Pattern 和 Verbalizer 会产生差异很大的结果。

5.3 从实验数据中读出的关键结论

案例一：标签词的"自然性"决定性能上限（SST-2 任务）

  • 最佳组合：模板 It was [MASK]. + 标签词 great/terrible，准确率高达 92.7。
  • 对比实验 1（中性词）：标签词调换为 good/bad，性能轻微下降至 92.5，说明 great/terrible 这类情感更强烈的词更适合情感分析任务。
  • 对比实验 2（完全不相关词，灾难性后果）：标签词换为 cat/dog，性能显著下降至 91.5；顺序颠倒为 dog/cat，性能暴跌至 86.2！证明标签词必须与任务语义相关，且顺序固定。
  • 对比实验 3（颠倒标签映射）：将 great/terrible 颠倒为 terrible/great（即让"正面"标签对应"terrible"），准确率骤降至 83.2。证明标签词与类别之间的映射关系必须合乎逻辑。

案例二：模板的"通顺度"直接影响效果（SNLI 任务）

  • 使用较通顺的模板 [MASK],，准确率 76.2；模板变为不自然的 [MASK] 时，准确率下降至 62.9。说明模板本身应该是符合语法的自然句子，才能最好地激活模型的语言知识。

案例三：PET 显著优于传统微调

  • 表格最后一行显示，在两个任务上，即使表现最差的 PET 配置，效果也远高于传统 Fine-Tuning 方法：
    • SST-2：Fine-tuning 81.4 vs PET 最低 86.2
    • SNLI：Fine-tuning 48.4 vs PET 最低 60.6
  • 这强有力地证明了 Prompt-Tuning 范式的优越性。

注意：采用人工构建 Pattern 和 Verbalizer 的方法成本高，需要与领域任务相关的先验知识。

6. 人工设计 PVP 的三大缺陷

人工设计 Pattern 和 Verbalizer（合称 PVP）存在三大核心缺陷，这决定了它无法成为大规模应用的基础：

1. 成本高昂，依赖"炼丹经验"

为每个新任务设计有效的 PVP，需要研究者对该领域有深厚的先验知识，并且要反复"猜测-验证-调整"，过程如同"炼丹"，效率极低，无法规模化。

2. 效果不稳定，方差大

"不同的 PVP 对结果产生的差异明显，方差大"。精心设计的方案可能还不如随手一试的方案。模型性能极度敏感于 PVP 的选择，导致结果不可靠、难以复现。

3. 与预训练任务存在"分布差异"（最深刻的问题）

BERT 等模型的 MLM 预训练任务，并没有按照人工设计的、带有明确任务指令的 PVP 模式进行（例如预训练时它看到的是"今天天气很[MASK]"，而不是"这句话的情感是[MASK]"）。

  • 后果：这种"分布差异"使人工设计的 PVP 可能无法最有效地激活模型在预训练时学到的知识——相当于用一套模型不熟悉的"密码本"去下指令，效果打折扣。

转折点

正因上述缺陷，课程提出了那个价值连城的问题："如何能够自动地挑选合适的 PVP？"

这个问题是整个提示学习领域从"手工作坊"迈向"工业化生产"的转折点，宣告了"人工设计"时代的局限性，引出了课程的主角——一系列旨在实现自动化、最优化 Prompt 的 Prompt-Tuning 方法。

简单来说，接下来的研究目标非常明确：用算法和机器学习的力量取代人工的"猜"和"试"，让机器自己去寻找打开它自身知识宝库的那把"最优钥匙"。

7. Prompt-Oriented Fine-Tuning：面向提示的微调

Prompt-Oriented Fine-Tuning 的本质：将目标任务转换为适应预训练模型的预训练任务，以适应预训练模型的学习体系。

7.1 以情感分析任务为例

BERT Fine-Tuning（传统微调）流程

  • 将训练文本经过 BERT 编码后生成向量表征，再利用该向量表征连接全连接层，实现最终的情感类别识别。
  • 显式弊端：预训练任务与下游任务存在 gap（差异）。
    • 预训练任务：BERT 在掩码语言模型（MLM）任务上训练，核心是"猜词"。
    • 下游任务：情感分类是一个全新的"分类"任务。
    • 问题所在：为了让模型做好分类，不得不让它"忘记"一部分熟悉的猜词能力，去"学习"一个全新的分类技能。相当于让一个语言学家转行做选择题考官，中间必然有损耗和适应过程。

Prompt-Oriented Fine-Tuning 流程

  • 步骤一：构建提示（Prompt）：设计一个包含 [MASK] 的模板，例如 It was [MASK].
  • 步骤二：拼接输入：将提示与原始文本拼接，形成新输入，如 It was [MASK]. The film is attractive.
  • 步骤三：执行训练：将这个新句子输入预训练模型（如 BERT），训练任务目标直接就是模型预训练时的 MLM 任务目标——预测 [MASK] 位置应该是什么词。

7.2 革命性优势

  • 消除 Gap：下游任务的目标（预测情感）和预训练任务的目标（预测被掩码的词）完全一致！模型不需要学习任何新东西，而是在直接调用它最原始、最强大的核心能力。
  • 更高效的数据利用：因为任务形式与预训练一致，模型能更充分利用预训练中获得的知识，通常在小样本场景下表现尤为出色。
  • 更直觉的推理：通过标签词映射（Verbalizer），将模型预测出的词（如 great）映射到情感类别（如正面），比理解一个分类器的数字输出更符合直觉。

核心思想一句话：不再让模型来适应我们的任务，而是让我们的任务去适应模型！

8. P-Tuning V1：连续提示向量优化（NLU 任务）

8.1 直接优化 Embedding 参数的两个挑战

P-Tuning V1 直接对 Embedding 参数进行优化会存在两个挑战：

  1. Discreteness（不连续性）：对输入正常语料的 Embedding 层已经过预训练，如果直接对输入的 prompt embedding 进行随机初始化训练，容易陷入局部最优。
  2. Association（关联性缺失）：无法捕捉到 prompt embedding 之间的相关关系。

8.2 核心思想与结构

  • 核心思想：用 MLP + LSTM 的方式对 prompt embedding 进行一层处理。
  • 公式：
    h_i = MLP( [ h_i→ : h_i← ] )
    = MLP( LSTM(h_0i) : LSTM(h_im) )
  • 总体思路：P-tuning 固定 LLM 参数，利用多层感知机（MLP）和 LSTM 对 Prompt 进行编码，编码之后与其他向量拼接后正常输入 LLM。注意：训练之后只保留 Prompt 编码之后的向量即可，无需保留编码器。

8.3 两大挑战的深入理解

  • 不连续性：
    • 问题：预训练模型本身的词嵌入是经过海量数据训练好的，已形成光滑有意义的语义空间；而直接随机初始化提示向量并训练，这些向量可能与预训练好的嵌入空间不匹配，导致优化陷入局部最优、效果不佳。
    • 比喻：让一个习惯了听摇滚音乐的耳朵，去欣赏一段完全随机、不和谐的音符，很难得到好的反馈。
  • 关联性缺失：
    • 问题：一个有效的提示模板（如"这部电影很[MASK]"）其中的词汇是有语法和语义关联的；如果把提示向量都当作独立的个体进行优化，无法捕获向量之间应有的前后依赖关系。
    • 比喻：把一句话里的每个字拆散，让不同的人独立记忆，拼凑起来很可能已经失去原句的含义和流畅度。

8.4 P-Tuning V1 的实现步骤

  1. 步骤一：输入"伪提示词"——不再使用真实词汇，而是定义一组"伪令牌"，例如 [P0], [P1], [P2], …。这些令牌没有实际含义，只是可训练参数的"占位符"。

  2. 步骤二：核心创新——"提示编码器"——伪令牌的嵌入向量不会直接使用，而是送入提示编码器（通常由双向 LSTM 和 MLP 组成）：

    • 双向 LSTM 的作用：建模提示词之间的序列依赖关系，确保每个位置的提示向量都能感知其左右上下文，从而学习到像真实词汇一样的前后关联性，解决"关联性缺失"问题。
    • MLP 的作用：将 LSTM 的输出向量映射到一个更平滑、与预训练模型嵌入空间更兼容的区域，解决"不连续"问题。
    • 经过编码器处理后，得到一组"成熟"的、蕴含关联和上下文信息的连续提示向量。

  3. 步骤三：拼接输入、送入预训练模型——将这些优化后的连续提示向量与原始输入文本的嵌入向量拼接，形成新的模型输入；将完整输入序列送入参数被冻结的预训练语言模型（如 GPT、BERT 等）。

  4. 步骤四：梯度反向传播和参数更新——梯度会反向传播，但预训练语言模型本身的参数被"冻结"，梯度在此处被阻断、不予更新。梯度只用于更新两部分参数：

    1. 提示编码器（LSTM 和 MLP）的参数；
    2. 伪提示词的初始嵌入向量。

9. 一句话总结

NLP 历经"传统机器学习 → 深度学习 → 预训练+微调 → 预训练+提示"四大范式；Prompt-Tuning 正是第四范式下的核心方法论——从 GPT-3 的 ICL 思想出发，经由 PET 的 PVP 框架（Pattern 模板 + Verbalizer 标签词映射），解决了人工设计 PVP 成本高、方差大、与预训练分布不一致三大缺陷，最终发展出 Prompt-Oriented Fine-Tuning 与 P-Tuning（连续提示向量）等让中小模型也能复现大模型提示能力的自动化技术。

10. 补充：现代真实生产环境的主流微调方式

现在企业大模型落地，几乎全部选用 PEFT（参数高效微调），几乎不做全量 Fine-tuning。主流方案优先级排序如下：

方案 生产地位 典型场景 核心特点
LoRA ✅ 生产首选，最常用 企业私有化部署、行业知识库、领域模型微调、Agent、对话模型（LLaMA、Qwen、GLM 等开源模型标配） 只训练低秩矩阵，冻结基座大模型；训练参数通常 <1%；显存占用低；产出 LoRA 权重仅几十 MB；推理时可将 LoRA 权重合并进基座模型，推理无额外开销、速度不变
Prefix-Tuning ⚠️ 次常用（序列生成类场景） 对话生成、摘要、文案生成等自回归任务；早期 GPT 类模型微调常用 在 Transformer 每一层增加可训练前缀向量；不改动模型主干；缺点：推理需一直携带前缀，增加显存开销，速度略降
Prompt Tuning ⚠️ 多用于超大模型（>10B） 百亿以上超大基座、以分类任务为主 只在输入层增加少量可训练伪 token；参数量最小；模型规模越大效果越好，小模型基本失效
Adapter Tuning ⚠️ 部分场景使用 多任务场景，需同时维护多个任务适配器 在 Transformer 层插入小型 Adapter 子网络；多个任务可加载不同 Adapter 切换；缺点：推理时增加网络计算量，推理变慢

补充说明：

  • 全量 Fine-tuning：生产环境极少使用。只有财力极强、需要深度重塑基座能力的场景才会考虑，成本极高。
  • P-Tuning V1 / PET：属于学术论文方案，工业几乎不用，仅作为 Prompt Tuning 发展历史原型。
  • ICL、CoT、Instruction Tuning：本质不是微调算法，而是训练范式；其中 Instruction Tuning 常配合 LoRA 一起使用。

11. 理论方案 vs 真实生产环境的差距

11.1 PET / P-Tuning V1（早期方案）

✅ 理论价值：Prompt Tuning 的开山工作，提出 PVP 模板、连续提示词思路，证明任务可以改造为"填空"形式适配预训练模型。

❌ 生产落地缺陷：

  1. P-Tuning V1 依赖双向 LSTM + MLP 编码 prompt 伪 token，结构复杂，推理会引入额外计算，工程实现麻烦；
  2. 早期 PET 依赖人工设计 Pattern 模板和 Verbalizer 标签映射，人工成本高、结果方差巨大，难以稳定用于大量业务；
  3. 泛化差，不同任务需重新设计模板，很难工业化批量部署；
  4. 仅适合 BERT 类编码器模型，不适合现在主流的自回归大模型（Qwen、LLaMA）。

结论：只存在于论文和课程，生产几乎不使用。

11.2 Prompt Tuning

✅ 理论结论：超大模型下，仅学习输入层少量伪 token 就能达到接近全量微调的效果。

❌ 生产限制：

  1. 强依赖模型规模：模型小于 10B 参数时效果暴跌，中小企业的小基座模型不能用；
  2. 只在输入层加 token，对复杂任务、长文本任务能力上限不如 LoRA；
  3. 多任务切换灵活性弱于 LoRA。

11.3 Prefix-Tuning

✅ 理论：每一层 Transformer 都添加可训练前缀，捕获更深层信息，效果优于基础 Prompt Tuning。

❌ 生产短板：

  1. 每一层都增加前缀向量，推理阶段显存占用持续增加，序列越长开销越高；
  2. 不能把权重合并到基座模型，推理始终带额外开销。

现在逐步被 LoRA 替代。

11.4 Adapter Tuning

✅ 理论：插入独立小网络，多任务之间互不干扰，任务热切换友好。

❌ 生产短板：推理时必须走 Adapter 子网络，推理速度永久下降；线上高并发、延迟敏感业务不适用。

11.5 LoRA（工业首选）

真实生产环境对 LoRA 做了大量工程优化，已超出原始论文版本：

  1. 原始论文 LoRA 只针对 Transformer 的 Attention 的 Q/K 矩阵；工业上扩展到 QKV / MLP 都可加 LoRA，提升领域拟合能力；
  2. 动态权重加载：多业务场景下基座模型常驻显存，按需加载不同 LoRA，无需重复加载整个大模型；
  3. LoRA 权重合并：训练完可将低秩矩阵合并进基座权重，推理时完全没有额外开销，速度和原始基座一致——这是 LoRA 最大的生产优势；
  4. 配套工具链成熟：peft、transformers、llama-factory 等开箱即用，支持分布式训练、量化训练（4bit/8bit QLoRA），单张消费卡即可微调 7B 模型。

12. 整体对比总结表

方案 讲义定位 生产落地情况 核心差距
PET Prompt Tuning 鼻祖，PVP 模板 ❌ 几乎不用 人工模板成本高，泛化不稳定，工程繁琐
P-Tuning V1 解决离散提示词不连续问题 ❌ 几乎不用 LSTM 结构增加推理开销，仅适配 BERT
Prompt Tuning 输入层加伪 token ⚠️ 仅限 >10B 超大模型 小模型效果差，任务能力上限低
Prefix Tuning 每层 Transformer 添加前缀 ⚠️ 少量生成场景使用 推理显存开销大，无法合并权重
Adapter Tuning 插入适配器子网络 ⚠️ 多任务场景少量使用 推理速度永久变慢
LoRA PEFT 其中一种方案 ✅ 生产环境首选 讲义只讲基础原理；工业扩展了 QLoRA、多模块 LoRA、权重合并等工程能力
全量 Fine-tuning 传统微调范式 ❌ 极少使用 显存/算力成本巨大，容易灾难性遗忘

13. 生产环境的完整链路（重点）

工业不会单独只用某一种 PEFT，常见组合方式：

  1. Instruction Tuning + LoRA：用指令数据集通过 LoRA 做指令微调，对齐模型遵循指令的能力；
  2. SFT(LoRA) + DPO/ORPO：模型微调后继续做偏好对齐，优化对话输出质量；
  3. RAG + LoRA：LoRA 负责领域风格 / 输出格式对齐，RAG 负责外部知识库的事实增强。

生产选型总结：讲义偏算法理论演进；真实生产环境选型优先看 显存成本、训练速度、线上推理延迟、部署复杂度、多任务管理能力，而不是单纯看任务准确率。
